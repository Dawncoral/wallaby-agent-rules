# Quickstart: the first success, offline

Run the fictional demo first, then initialize your own project and check it.
The demo needs no model, API key, network, or git repository.

```bash
# 1. run the fictional example in a temporary copy
python3 extras/memory-governance/quickstart.py demo

# 2. create the memory files in a project; existing files are kept
python3 extras/memory-governance/quickstart.py --target /path/to/project init

# 3. check the result
cd /path/to/project
python3 scripts/memory_governance.py --target . doctor
```

On Windows, use `python` or `py` in place of `python3` if `python3` is not on PATH.

The demo prints `Doctor: PASS` on its last line and exits 0 only when
`reconcile.py`, `health_check.py`, and the governance `doctor` all exit 0.
The real project's `doctor` prints `DOCTOR OK` when its checks pass.

## What `init` creates

| File | What it is |
|---|---|
| `AGENTS.md` (or `CLAUDE.md`, `GEMINI.md`, `.cursorrules`) | The entry file: standing instructions for the AI |
| `README.md` | A minimal onboarding entry, created only when no README exists |
| `MEMORY.md` | Permanent facts and iron rules, one dated line each |
| `NOW.md` | Work in flight and recently touched |
| `INDEX.md` | One line per file, generated from relative paths and suffixes |
| `LOG.md` | Dated append-only log, with one initialization line |
| `scripts/health_check.py` | The weekly tidy-up check |
| `scripts/reconcile.py` | The LOG.md/NOW.md contradiction audit |
| `scripts/memory_governance.py` | The installed governance CLI |
| `.memory/` | Governance data: impact map, premises, contradictions, receipts |

The entry file is chosen from what the project already has:

- Any existing `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, or `.cursorrules` is kept.
- With only a `.claude/` directory, `CLAUDE.md` is created.
- With only a `.gemini/` directory, `GEMINI.md` is created.
- Otherwise `AGENTS.md` is created.

`init` never overwrites, merges, or repairs an existing file. A second run
prints `KEEP` for every existing file, changes no bytes, and changes no mtime;
`LOG.md` does not get a second initialization line. It is safe to run again
after an interrupted run. New files are created exclusively, paths stay inside
the target, and symlinks inside the target are not followed.

An existing entry file is a safe starting point, not an upgraded one. Its
output points to **PROMPT.md → L2 — Upgrade check** for an item-by-item,
approval-gated content upgrade.

`INDEX.md` is generated by walking relative file names and allowed suffixes
(`.md`, `.py`, `.json`, `.yaml`, `.yml`, `.toml`, `.txt`, `.sh`, `.js`, `.ts`,
`.html`, `.css`, `.sql`). It does not read project content, does not guess
project facts, and never includes `.git/`, `.credentials/`, or `.env*`.

## What `demo` does

`demo` copies [`examples/first-success/`](../examples/first-success/) into the
system temporary directory. The repository copy is hashed before and after and
is never modified. In the copy it:

1. runs the full `init`;
2. asks the real Memory MCP `memory_locate` for the fictional export-format
   decision and gets the `docs/export-decision.md` row from `INDEX.md`;
3. reads the decision from that document;
4. shows a second item that `LOG.md` calls done while `NOW.md` still lists it in
   flight, and requires `reconcile.py` to exit 1;
5. removes that one finished line from the temporary `NOW.md`;
6. requires `reconcile.py`, `health_check.py`, and the governance `doctor` to
   exit 0.

The example's `2026-01-05` becomes yesterday and `2026-01-06` becomes today in
the temporary copy, so the demonstration does not go stale. A real project is
never edited.

## Your first real lookup

A newly initialized project does not contain your project's history. Give it
one real fact before testing recall:

1. Ask the agent in that project to record one real decision and its source.
   If your setup proposes new memories for approval, approve that entry.
2. Start a fresh session in the same project.
3. Ask: `What did we decide about <topic>? Show the source entry.`
4. Open the memory entry or linked source document named in the answer.

The offline demo cannot prove this real lookup for you. A missing decision must
produce an honest miss, not an automatic expansion of the query. An agent that
reads the entry file can use the Markdown files directly; the optional MCP
entry below adds the same read and locate operations as tools.

## The optional MCP entry

`mcp-config --print` prints one `mcpServers` entry; it does not scan or write
client configuration:

```bash
python3 extras/memory-governance/quickstart.py --target /path/to/project mcp-config --print
```

```json
{
  "mcpServers": {
    "wallaby-memory": {
      "command": "/usr/bin/python3",
      "args": [
        "/path/to/wallaby-agent-rules/extras/memory-mcp/wallaby_memory_mcp.py",
        "--root",
        "/path/to/project"
      ]
    }
  }
}
```

Merge only the `wallaby-memory` key into the client's existing `mcpServers`
object. Do not replace the whole configuration. Restart the client, ask it to
call `memory_read`, then use `memory_locate` for the real decision above. See
[Clients](clients.md).

## Limits

- Python 3.9 or newer. Nothing is installed with pip or npm.
- No devcontainer, Codespaces, Node, Go, vector store, semantic index, or model
  summarization.
- `init` does not index or repair a project's existing files; it only adds the
  missing memory files and the entry file.
- The demo's `Doctor: PASS` is the package's own success condition, not a
  generic health guarantee for a real project.
- The CI matrix in
  [`.github/workflows/quickstart.yml`](../.github/workflows/quickstart.yml)
  covers Ubuntu, macOS, and Windows on Python 3.9 and 3.12. The hot-reload
  test runs on POSIX and prints an explicit skip on Windows. This workflow was
  added with this package; it has not been run on GitHub yet.
