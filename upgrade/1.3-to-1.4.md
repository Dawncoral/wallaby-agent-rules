# Upgrade from 1.3.0 to 1.4.0

Nothing needs to move. Your existing MEMORY.md, NOW.md, INDEX.md, LOG.md, and both check scripts keep working, so you can review each addition without rebuilding the memory system your project already uses.

## Optional additions

Copy any of these files into your project:

- `templates/MAP.md` — map system components and the surfaces a change may affect.
- `templates/CAPABILITIES.md` — register reusable tools before building another one.
- `templates/FAILURES.md` — turn memory failures into regression cases.

`examples/FAILURES.example.md` contains ten sanitized composite entries. Use their structure; do not copy them as incidents from your own project.

If you add any of the three templates at the project root, use health check 1.4.0. Its only change adds MAP.md, CAPABILITIES.md, and FAILURES.md to the root whitelist, so the tidy-up scan does not report them as stray files.

## Optional governance pack

Install conduction, premise checks, contradiction history, and verification receipts:

```bash
python3 extras/memory-governance/memory_governance.py --target /path/to/your-project init
cd /path/to/your-project
python3 scripts/memory_governance.py doctor
```

The pack creates `.memory/` and copies the CLI to `scripts/`. It never overwrites existing files. A fresh `doctor` ends with `DOCTOR OK`; your first impact receipt starts as pending and turns verified only after old references are resolved or explicitly allowed.

## Closeout wording

Add this rule to your entry file or closeout procedure:

> When tracked work closes, write LOG.md and update NOW.md in the same action. Pending entries use `<anchor> — <current status>`; never "later" or another deferral placeholder.

The installable `agent-memory-rules` skill carries the same update in skill version 1.1.0.
